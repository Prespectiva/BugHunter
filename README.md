# BugHunter

## 1. Название проекта

**BugHunter** — система учёта дефектов (баг-трекер). Практическая работа №9: документация и развёртывание.

## 2. Описание

BugHunter помогает команде тестирования и разработки фиксировать ошибки в проектах, вести их по жизненному
циклу (New → Review → Confirmed → In Progress → Fixed → Closed / Rejected), обсуждать в комментариях и
анализировать статистику. Роли: заказчик, тестировщик, разработчик, администратор.

## 3. Функциональность

- регистрация и вход, роли и права доступа;
- проекты (создание, правка, просмотр, удаление пустого проекта);
- ошибки: регистрация, карточка, редактирование;
- смена статуса по допустимым переходам, история изменений;
- комментарии с автором и датой;
- поиск, фильтры, сортировка, пагинация, экспорт в CSV;
- Dashboard со статистикой;
- защита: PDO prepared statements, экранирование вывода, CSRF-токены, серверная проверка прав;
- резервное копирование и восстановление базы, проверка целостности, автопроверка страниц.

## 4. Технологии

PHP 8+, SQLite 3 через PDO, HTML, CSS (без JavaScript и сторонних библиотек), встроенный сервер PHP для демонстрации.

## 5. Требования

- PHP 8.1 или новее (`php -v`);
- расширения `pdo`, `pdo_sqlite`, `sqlite3`, `mbstring` (`php -m`);
- права записи в каталоги `storage/` и `backups/`;
- браузер с поддержкой HTML5.

## 6. Установка

1. Скопируйте проект в любую папку (например, `C:\bughunter` или `~/bughunter`).
2. Проверьте окружение: `php -v` и `php -m` (в списке должны быть pdo_sqlite и mbstring).
3. Создайте базу данных и тестовые пользователи:

   ```
   php scripts/init_db.php
   php scripts/migrate.php
   ```

4. Демонстрационные данные (25 ошибок и комментарии, по желанию):

   ```
   php scripts/seed_demo.php
   ```

5. Проверьте целостность базы: `php scripts/integrity_check.php`.

Файл базы создаётся в `storage/bughunter.db`. Если у вас уже есть база от прежней версии проекта
(`data/bughunter.db`), скопируйте её в `storage/bughunter.db` и выполните `php scripts/migrate.php`.

## 7. Запуск

```
php -S 127.0.0.1:8000 -t public
```

Откройте http://127.0.0.1:8000/ и войдите под тестовой учётной записью (раздел 9).
Встроенный сервер PHP предназначен для разработки и демонстрации, а не для публичного размещения.
Параметр `-t public` обязателен: корнем сайта должна быть только папка `public/`, тогда база данных,
конфигурация и исходный код библиотек недоступны по URL.

Автопроверка страниц (при запущенном сервере, в другом окне консоли):

```
php scripts/smoke_test.php http://127.0.0.1:8000
```

Резервная копия и восстановление:

```
php scripts/backup.php
php scripts/restore.php backups/bughunter_ГГГГММДД_ЧЧММСС.db
```

## 8. Структура каталогов

```
BugHunter/
├── public/        web-root: страницы (login, bugs, projects, dashboard, ...) и style.css
├── app/           библиотеки: auth, bugs_lib, projects_lib, search_lib, logger
├── config/        database.php — подключение PDO
├── database/      schema.sql — схема БД
├── storage/       bughunter.db и error.log (создаются автоматически, вне web-root)
├── backups/       резервные копии базы (вне web-root)
├── scripts/       init_db, migrate, seed_demo, check, integrity_check, smoke_test, backup, restore
├── docs/          ER-диаграмма, схема архитектуры, сценарий демонстрации
└── README.md
```
