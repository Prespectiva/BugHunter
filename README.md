# BugHunter

## 1. Назначение проекта

BugHunter — учебная веб-система учёта дефектов (баг-трекер) для команды тестирования и разработки.
Она позволяет регистрировать ошибки в проектах, вести их по жизненному циклу
(New → Review → Confirmed → In Progress → Fixed → Closed / Rejected), обсуждать в комментариях,
искать и фильтровать списки и просматривать сводную статистику на панели Dashboard.
Роли пользователей: заказчик (customer), тестировщик (tester), разработчик (developer), администратор (admin).

## 2. Требования к окружению

- PHP 8.1 или новее (расширения `pdo_sqlite`, `sqlite3`, `mbstring`);
- SQLite 3 (входит в расширение `pdo_sqlite`, отдельная установка не нужна);
- современный браузер; JavaScript не требуется (кроме подтверждения удаления проекта).

## 3. Инструкция запуска

1. Распакуйте проект в папку, например `bughunter/`.
2. В консоли перейдите в папку проекта и создайте базу с тестовыми данными (только из консоли):

   ```
   php init_db.php
   php migrate.php
   php seed_demo.php        # по желанию: демо-ошибки для проверки пагинации
   ```

3. Запустите сервер с роутером, который закрывает папки `data/`, `config/` и `database/`:

   ```
   php -S localhost:8000 router.php
   ```

4. Откройте http://localhost:8000/ и войдите под тестовой учётной записью.
5. Проверки: `php integrity_check.php` (целостность БД) и, при запущенном сервере,
   `php smoke_test.php http://localhost:8000` (автопроверка страниц).

На Apache доступ к `data/`, `config/` и `database/` закрывают файлы `.htaccess` из этих папок.
Для nginx закройте эти каталоги в конфигурации сервера самостоятельно.

## 4. Структура каталогов

```
bughunter/
├── config/database.php     подключение PDO к SQLite (PRAGMA foreign_keys = ON)
├── database/schema.sql     схема БД: таблицы, ограничения, индексы
├── data/                   файл БД bughunter.db и лог error.log (закрыта от доступа по URL)
├── auth.php                сессии, вход, CSRF, errorPage(), шапка страниц
├── bugs_lib.php            логика ошибок: статусы, переходы, права, валидация
├── projects_lib.php        логика проектов
├── search_lib.php          поиск, фильтры, сортировка, пагинация
├── login.php, register.php, logout.php
├── projects.php, project_*.php
├── bugs.php, bug_view.php, bug_create.php, bug_edit.php
├── bug_status_change.php, comment_add.php
├── dashboard.php           статистика
├── init_db.php, migrate.php, seed_demo.php   подготовка БД (консоль или admin)
├── check.php, integrity_check.php            проверки БД
├── smoke_test.php          автопроверка страниц по HTTP
├── router.php              роутер для php -S
├── guard.php, logger.php   защита служебных скриптов и лог ошибок
└── style.css
```

## 5. Описание возможностей

- Регистрация и вход, пароли хранятся только в виде `password_hash()`.
- Проекты: создание, просмотр, правка владельцем или администратором, запрет удаления проекта с ошибками.
- Ошибки: регистрация, карточка, редактирование автором, исполнителем или администратором.
- Статусы: 7 статусов, карта допустимых переходов и права ролей, история в `bug_history` (транзакция PDO).
- Комментарии с автором и датой, единая лента с историей.
- Поиск по тексту, фильтры, сортировка, пагинация, экспорт в CSV, Dashboard.
- Защита: подготовленные выражения PDO, `htmlspecialchars()`, CSRF-токены во всех POST-формах,
  серверная проверка прав, защитные заголовки, лог критических ошибок `data/error.log`.

## 6. Тестовые данные

После `php init_db.php` создаются демонстрационные пользователи (по одному на роль):

| Роль          | E-mail             |
|---------------|--------------------|
| customer      | customer@bh.local  |
| tester        | tester@bh.local    |
| developer     | dev@bh.local       |
| admin         | admin@bh.local     |

Реальных паролей пользователей в проекте нет. Общий демонстрационный пароль для этих учётных записей
задаётся в `init_db.php` (строка с `password_hash`); перед публикацией проекта его нужно сменить.
Также создаются проекты BH и SITE и три тестовые ошибки; `seed_demo.php` добавляет ещё 25 демо-ошибок.
